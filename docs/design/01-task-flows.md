# Shellune 任务流与体验目标（R12、R13 调研记录）

本文件记录 R13 要求的 UI/UX 调研结果。调研以真实任务为单位，先写清用户要完成什么、在
哪一步容易迷失、失败时必须看到什么，再据此决定导航与呈现。此前讨论过的"左侧主机栏 +
顶部标签 + 中央终端 + 固定 SFTP 面板"没有被当作需求，也没有被直接否掉：它只是候选方案
之一，最终结构由下列任务流决定。

## 1. 调研输入与方法

- 输入：需求文档 R1—R18；执行计划 T3—T10 明确的能力边界（本地终端、主机管理与导入、
  主机信任与认证、多会话、SFTP 浏览与修改、上传下载）；当前平台为 Windows 11 x86_64。
- 方法：为每个任务写出"入口 → 步骤 → 必须可辨认的对象 → 失败时的可见结果"，凡是无法在
  这一步给出确定答案的地方，就是界面必须显式表达的状态。
- 结论只决定交互与视觉，不删减能力：多会话、SFTP、传输、错误恢复都必须有入口，即使当前
  版本尚未实现，也只能显示"当前版本未包含"，不能显示成功。

## 2. 任务流

### 2.1 首次打开

1. 用户打开 Shellune，**第一眼就要看到四种对象**：本地终端、主机、会话、传输。
2. 第一帧必须能回答"我现在在哪里、这里有什么、下一步做什么"。
3. 未实现的能力直接说明"当前版本未包含"，并说明下一步会提供什么，不显示空列表了事。

设计的直接结果：导航栏固定四项；每个分区都有状态标签（未包含 / 空 / 加载中 / 失败 /
有内容）；主按钮在能力缺失时呈现为不可用样式，点击后明确提示"没有启动任何任务"。

### 2.2 本地终端

1. 入口：导航"本地终端"或主按钮"新建本地终端"。
2. 必须可辨认：会话名称、类型（Local）、Shell 可执行文件、生命周期状态。
3. 失败：Shell 不存在或无权限时显示真实原因与"选择 Shell"这样的下一步，不生成假会话。

设计的直接结果：会话行固定三段信息（名称 / 类型 · 状态 / 状态标签），失败原因使用
`SessionFailure` 的原文，而不是"出错了"。

### 2.3 导入或新建主机

1. 入口：导航"主机"，主按钮"新建主机"；导入 SSH 配置作为同一分区的第二个动作。
2. 必须可辨认：主机名、`user@address:port` 目标、分组。
3. 保存成功不等于连接成功：保存后主机行只显示配置信息，状态保持中性。

设计的直接结果：主机行不出现任何"已连接"字样的位置；连接状态只属于会话。

### 2.4 认证与信任

1. 未知主机先展示算法与 SHA-256 指纹，用户接受后才进入终端。
2. 拒绝后再无终端界面，只留下失败原因与"重试 / 更换方式"。
3. 密码、口令输入始终遮蔽，错误文本不含秘密。

设计的直接结果：状态机把"校验主机身份"和"认证中"作为独立状态显示（Warning 色调），
"已连接"只在真正连上后出现（Positive 色调），两者使用不同颜色与文案。

### 2.5 多会话切换

1. 同时打开本地与多个远程会话，切换时当前对象始终可见。
2. 一个会话断开只改变它自己的状态，其他会话保持原样。
3. 会话行必须能区分"同一个主机的两个会话"——因此标题不是唯一识别依据，状态与类型同时显示。

设计的直接结果：导航显示会话总数；会话分区按打开顺序列出全部会话；当前分区由导航选中态
与标题双重表达。

### 2.6 SFTP 浏览、修改与传输

1. 从远程会话打开文件视图，不重复输入凭据；主机与当前路径常驻可见。
2. 新建目录、重命名、删除都有目标确认；删除展示完整目标与类型，非空目录说明递归影响。
3. 上传下载展示源、目标、进度、完成或失败；同名目标写入前要求选择覆盖。

设计的直接结果：传输作为独立导航分区（与"会话"并列），列表行固定显示方向、源、目标与
状态；只有 `Completed` 使用 Positive 色调。

### 2.7 错误恢复

1. 每个失败都必须回答三件事：发生了什么、为什么、下一步能做什么。
2. 等待与失败不得阻塞其他分区：导航始终可点。

设计的直接结果：失败卡片固定包含原因文本与"建议的下一步"（重试 / 新建主机 / 导入配置 /
选择 Shell）；导航与主按钮在任何状态下都不被禁用。

## 3. R12 到设计的映射

| R12 要求 | 设计上的落点 | 当前验证方式 |
| --- | --- | --- |
| 常用任务入口可发现 | 四项固定导航 + 每区一个主按钮 + 数字快捷键 | GPUI 测试读取四个导航入口与主按钮的实际布局框 |
| 当前对象与状态易辨认 | 标题行"当前对象 · 名称"、标题、状态标签、导航选中态与强调条 | 布局测试 + 运行窗口像素统计 |
| 文字清楚、层级协调 | 三级字号 + 两级文字颜色 + 状态色，全部经对比度测试 | `body_text_reaches_the_contrast_floor_on_every_surface` |
| 错误说明原因并可行动 | 失败卡片 = 原因 + 建议下一步；能力缺失有明确提示 | `a_failed_section_stays_failed_after_the_primary_action_is_requested` |
| 连接与文件操作不阻塞其他交互 | 导航与切换不依赖分区状态；分区状态是数据而非锁 | 模型测试：任意状态下导航可切换 |
| 尊重各系统输入习惯 | Windows/Linux 用 Ctrl+1-4，macOS 用 ⌘1-4；快捷键标签随平台变化 | `shortcuts_follow_each_platform_convention` |
| 显示缩放环境 | 文字大小 90%/100%/115% 三档，度量全部由同一 tokens 派生 | 最小窗口 + 最大字号下的布局测试 |

## 4. 未纳入本次调研的输入

- 视觉参考、品牌插画、主题切换：尚无已确认素材，因此只做单一深色主题，不虚构第二套主题。
- 三端字体与 IME 实际表现：需要 T11 的目标环境，当前只能验证 Windows 上的默认字体回退。
- 动效方案：本任务不引入动画；状态变化以颜色与文案表达，避免在未评审动效前先加动效。
